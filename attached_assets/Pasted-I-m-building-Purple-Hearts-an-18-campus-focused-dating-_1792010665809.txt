I'm building Purple Hearts, an 18+ campus-focused dating PWA. This project is exclusively the backend. The frontend is being developed separately by another developer and will be integrated later.

Use the following architecture:
- Node.js with TypeScript
- Express for the REST API
- PostgreSQL for persistent data
- Prisma ORM for database access and migrations
- Firebase Authentication for user authentication
- Cloudflare R2 for profile photo storage, to be integrated in a later phase
- Socket.IO for real-time messaging, to be integrated in a later phase
- Render for production API hosting

I want a maintainable, production-oriented backend rather than a quick prototype.

## Engineering requirements

- Never hardcode credentials, API keys, passwords, or tokens.
- Never expose secrets to the frontend.
- Use parameterized database access through Prisma.
- Do not use a mock database as a substitute for PostgreSQL.
- Do not claim that external services are connected unless they have actually been configured and tested.
- Do not automatically create paid external services or incur costs.
- Do not use destructive database commands against a production database.
- Keep the application compatible with deployment on Render.
- Bind the server to the port provided by process.env.PORT and to 0.0.0.0 in production.
- Separate development and production configuration.
- Make sure the application builds and its tests pass before declaring the phase complete.

For this phase, Firebase, Cloudflare R2, Socket.IO, and Paystack should be represented only in the documented future architecture. Do not implement placeholder integrations that appear functional but are not.
